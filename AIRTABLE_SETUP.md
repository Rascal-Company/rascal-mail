# Airtable Setup Guide

This guide explains how to set up Airtable as the prototype database for Rascal Mail.

## Overview

Rascal Mail uses a dual-database architecture:
- **Supabase (Rascal AI)**: Authentication only
- **Airtable**: Application data (prototype version)

This allows rapid prototyping without setting up a second Supabase project. Migration to Supabase is planned for production.

## Environment Variables

⚠️ **SECURITY WARNING**: The current implementation uses client-side Airtable queries, which exposes your API key in the browser. This is **NOT suitable for production** and should only be used for rapid prototyping.

### For Prototype/Demo (Current Implementation)

Add to your `.env.local` file:

```bash
# Supabase Auth (Rascal AI)
NEXT_PUBLIC_AUTH_SUPABASE_URL=your_supabase_url
NEXT_PUBLIC_AUTH_SUPABASE_ANON_KEY=your_anon_key

# Airtable (EXPOSED IN BROWSER - PROTOTYPE ONLY!)
NEXT_PUBLIC_AIRTABLE_API_KEY=your_airtable_api_key
NEXT_PUBLIC_AIRTABLE_BASE_ID=your_base_id
```

### For Production

**Before deploying to production**, you must:
1. Move all Airtable queries to server-side API routes (`/api/*`)
2. Remove `NEXT_PUBLIC_` prefix from Airtable credentials
3. Update hooks to call your API routes instead of Airtable directly

```bash
# Server-side only (NOT exposed to browser)
AIRTABLE_API_KEY=your_airtable_api_key
AIRTABLE_BASE_ID=your_base_id
```

### Getting Airtable Credentials

1. **API Key**:
   - Go to https://airtable.com/create/tokens
   - Create a new token with full access to your base
   - Copy the token

2. **Base ID**:
   - Open your Airtable base
   - Go to Help > API documentation
   - Find the base ID in the URL (e.g., `appXXXXXXXXXXXXXX`)

## Limitations in Demo Version

This prototype version has simplified functionality:

- ❌ No pagination for contacts
- ❌ No search/filtering
- ❌ No actual email sending (mock only)
- ❌ Hard-coded analytics data
- ❌ Limited CSV import (10 rows per batch due to Airtable limits)
- ❌ No webhook processing

## Migration Path to Supabase

When ready to migrate:

1. Create Rascal Mail Supabase project
2. Run `supabase/schema.sql` to create tables
3. Create migration script to copy data from Airtable to Supabase
4. Update environment variables to point to Supabase
5. Remove Airtable client and adapter code

The adapter pattern ensures minimal code changes during migration - only the data client implementation needs to change.
